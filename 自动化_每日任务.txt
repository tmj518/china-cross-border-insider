本工作区是 Landed Math（landedmath.com），一个英文内容站，把中国的一手官方数字变成外国买家发票上的钱。

你在无人值守的定时任务里运行（每天 08:10）。**先读这一节，它决定你不要在什么事上浪费时间。**

## 已知环境限制（不要试图修复它们）

这台机器上，`dsh headless` 运行在受限沙箱内，因此**有两件事必然失败**：

1. **`node node_modules/astro/bin/astro.mjs build` 会失败**，报 `require is not defined`（source-map-js / vite module-runner 的已知问题）。后果：`node tools/preflight.mjs` 里的构建检查会 BLOCK。
2. **`git push` 和 `git ls-remote` 会失败**，报 `couldn't create signal pipe, Win32 error 5`（沙箱禁止命名管道）。

**这两条不是你的任务。不要调试它们、不要改配置、不要换构建命令、不要清缓存。** 每次运行都在它们身上花掉整个会话，而结果不会变。

**这样做**：

- 质量靠这些闸门来保证，**它们在沙箱内都能正常跑**：`qa-check`、`serp-check`、`reviewer-check`、`link-check`。
- **本地 commit 可以**（`git add` 与 `git commit` 不依赖命名管道）。
- **push 交给人来做。** 在报告最后单独写一节「待推送」，列出这次产生的 commit 数量与 hash。

## 这一轮做什么

按「做法 C」：不依赖外部、先提升已有质量。

先读：
1. `项目规范_英文内容站_v1.3.md`（规则本体）
2. `初心与目标.md`（唯一裁决标准）
3. `进度日志.md` 的最后三节
4. `指令_完整版.md` 的「栏目轮换」一节

循环：
  取 `reviewBy` 最近到期的一篇
  → 对照它引用的一手来源重读
  → 有实质变化 → 公开更正（写进 frontmatter 的 `revisions` 和 `updatedDate`）
  → 无实质变化 → 明确记录「无需改动」，绝不只改日期
  → 跑闸门 → 本地 commit

同时执行栏目轮换：每栏目每周 1–3 篇。开工先查本周哪个栏目是 0 篇（`指令_完整版.md` 里有那段命令），有 0 篇的优先补。
如果最近到期的文章不需要改动，而某个栏目本周是 0 篇，就写一篇那个栏目的新文章。

写新文章时**优先只用仓库里已核实的数字**（不读新文件），那样最省。

## 硬性要求（违反任何一条都不得发布）

- frontmatter 长度：`title` ≤120、`subtitle` ≤160、`description` ≤300 字符。**超一个字符整个构建会失败。**
- `figures` ≥5 条，每条必须有 `value` / `unit` / `period` / `source` / `retrieved` 五项。
- `sources` ≥3 条，必须是一次文献（法规、公报、海关公告），不是二手报道。
- 正文至少一个带金额的每件/每柜/每吨成本表，且**必须调 `tools/` 里的模型**，不许即兴算术。
- 禁止模糊词：`may` / `might` / `possibly` / `perhaps` / `could` / `reportedly` / `allegedly`（月份 `May` 不受限）。
- `AI Summary` **必须恰好 40–60 词**。
- 必须有 `## How we calculated this`，把算式写出来。
- 每篇至少 1 条对外正文内链，**且不得形成 A→B 与 B→A 的环形对**。
- 每个数字都要能追到来源；查不到就写「查不到」，不要编。

## 交付

```
node tools/qa-check.mjs <文件>
node tools/serp-check.mjs <文件> --serp=file:data/serp/<文章名>.json
node tools/reviewer-check.mjs --all
node tools/link-check.mjs
git add -A && git commit
```

`preflight` 里的 astro 构建与 git remote 两项**已知会失败**，看其余项即可。
`node tools/feishu-sync.mjs` 也可以跑（走网络 API，不走命名管道）。

最后更新 `进度日志.md`。

## 报告（中文，必须含这五项）

1. 编号与类型（新文章 #N <slug>，或 更正 #N <slug>）
2. 这一轮做了什么，含实测数字（闸门几过、reviewer 几条、改了哪些文件）
3. 还哪些没做完，按等级
4. 需要用户给什么
5. **待推送**：这次产生了几个本地 commit、hash 是什么

任何一步失败，不要跳过也不要假装成功——把失败原因和你的判断写进报告，然后停下。**但不要为了修复已知的两项环境限制而反复尝试。**
