本工作区是 Landed Math（landedmath.com），一个英文内容站，把中国的一手官方数字变成外国买家发票上的钱。

先做四件事，再决定这一轮做什么：

1. 读 项目规范_英文内容站_v1.3.md（规则本体）
2. 读 初心与目标.md（唯一裁决标准）
3. 读 进度日志.md 的最后三节（上一轮做了什么、踩了什么坑）
4. 读 指令_完整版.md 的「栏目轮换」一节

然后跑：node tools/preflight.mjs  并确认全绿。

这一轮按「做法 C」做，也就是：不依赖外部、先提升已有质量。

循环是：
  取 reviewBy 最近到期的一篇
  → 对照它引用的一手来源重读（不读二手转述）
  → 有实质变化 → 公开更正（写进 frontmatter 的 revisions 和 updatedDate）
  → 无实质变化 → 明确记录「无需改动」，绝不只改日期
  → 跑三道闸门 → preflight → 上线核实 → 写飞书台账

同时执行「栏目轮换」规则：每栏目每周 1–3 篇。
开工时先查本周哪个栏目是 0 篇（指令_完整版.md 里有那段命令），有 0 篇的优先补。
如果最近到期的文章不需要改动，而某个栏目本周是 0 篇，那就写一篇那个栏目的新文章。

写新文章时，优先只用仓库里已核实的数字（不读新文件），因为那样最省。

硬性要求（违反任何一条都不得发布）：
- frontmatter 长度：title ≤120、subtitle ≤160、description ≤300 字符。超一个字符整个构建会失败。
- figures ≥5 条，每条必须有 value / unit / period / source / retrieved 五项。
- sources ≥3 条，必须是一次文献（法规、公报、海关公告），不是二手报道。
- 正文至少一个带金额的每件/每柜/每吨成本表，且必须调 tools/ 里的模型，不许即兴算术。
- 禁止模糊词：may / might / possibly / perhaps / could / reportedly / allegedly（月份 May 不受限）。
- AI Summary 必须恰好 40–60 词。
- 必须有 `## How we calculated this`，把算式写出来。
- 每篇至少 1 条对外正文内链，且不得形成 A→B 与 B→A 的环形对。
- 每个数字都要能追到来源；查不到就写「查不到」，不要编。

交付：
  node tools/qa-check.mjs <文件>
  node tools/serp-check.mjs <文件> --serp=file:data/serp/<文章名>.json
  node tools/reviewer-check.mjs --all
  node tools/preflight.mjs
全绿之后：
  git add -A && git commit && git push origin main
  node tools/feishu-sync.mjs
  更新 进度日志.md

最后用中文报告，必须包含这五项：
1. 编号与类型（新文章 #N <slug>，或 更正 #N <slug>）
2. 这一轮做了什么，含实测数字（闸门几过、构建几页、线上几项核实）
3. 还哪些没做完，按等级（卡凭据的 / 我能独立做的 / 等用户决定的）
4. 需要用户给什么（凭据或决定）
5. 成本

如果任何一步失败，不要跳过也不要假装成功——把失败原因和你的判断写进报告，然后停下。
