feat: structured data on every page, and the two identity nodes that were missing

The operator asked for two fixes from the SEO study: the five page types with no
structured data, and the missing Organization, BreadcrumbList and Article
author/publisher entities.

Both had the same root cause, which is why the fix is structural rather than five edits:
metadata was opt-in per page. A page got JSON-LD if whoever wrote it remembered, so the
calculator, tracker, markets, sources and the category hubs had none, and the next page
added would have had none either.

So src/lib/seo.mjs defines the nodes once and BaseLayout emits them on every page, with
the page-level block generated unless the page declares a more specific one. A new page
now gets correct metadata by existing.

What each node fixes:

  * Organization, with @id, url and logo. It was a bare name string before. The @id is
    the point: the Article blocks now reference one entity instead of repeating a name.
  * WebSite, tied to the organization rather than carrying its own publisher string.
  * BreadcrumbList, which the study flagged as the only structured data with required
    fields. The trail follows the URL, so it cannot drift from the information
    architecture. The homepage gets none, deliberately: a one-item trail is invalid and
    tells a machine nothing the canonical URL does not.
  * Article author as a node with a url pointing at /about/#who, and publisher as a
    reference to the organization. The byline is a pen name and Google's spam policies
    name fabricated creator profiles as deception, so the honest fix is not a fuller
    invented persona but making the existing name checkable against the real background
    already published.

Also removes the homepage's own WebSite block, which the layout now emits, and replaces
it with a CollectionPage - the homepage is an index of published analysis, and two
WebSite blocks on one page is the kind of duplicate that makes a machine pick wrong.

Adds tools/check-structured-data.mjs, wired into preflight. It checks every page type
carries WebSite, Organization and a page-level block, that no block type appears twice,
that BreadcrumbList has at least two ListItems and each carries position, name and item,
and that the two noindex pages carry nothing at all.

On dateModified: it is absent on this article, and that is correct rather than a gap.
The code emits it only when the article records a revision, because deriving it from the
review clock would turn a scheduled look into a claimed revision. I had described this
as a one-line omission earlier in the session; reading the code, it is deliberate and
right.
