# 错题本：过去一个月的错误与坑

写给两个读者：**写手 AI**（不要再写出来）和**审核 AI**（知道该盯哪里）。
也写给维护者：每一条都附了根因和现在拦它的规则。

规则顺序：现象 → 根因 → 谁在拦。
最后一条最重要：**这里记录的每一条，都是已经发生过一次的**。

---

## 一、内容造假的家族（最贵的一类）

### 1. 假设一个基线，然后在它上面算数
- **现象**：泰国电动车那篇假设现行税率 8%，算出 USD 8,100 / 240,000 / 810,000 和"337.5% 跳涨"；PET Spunbond 那篇假设 €3,500/吨，用在每张表和每个算例。两篇都上线了。
- **根因**：材料里没有现行税率/市场价，写手为了让文章"有算术"自己补了一个起点。写上 "assumed" 不等于有来源。
- **现在拦它**：闸门 `figure trace`（正文金额/百分比必须能追到 figures[]，或该段声明是示例）＋ 写手规则。

### 2. 编造条款号与程序名
- **现象**："Article 29"、"a filing-based regime"，材料里都没有。
- **根因**：模型熟悉这类文体的"标准说法"，会补一个听起来对的编号。
- **现在拦它**：写手规则（文件名字符串必须出现在材料里）＋ 审核意见（带 snippet）。

### 3. 给措施编动机和历史
- **现象**："a broader push"、"earlier crisis-response purchasing"。
- **根因**：政策文只写决定什么、何时生效，不写为什么。
- **现在拦它**：写手规则。

### 4. 把违规写成省钱手段
- **现象**：把低报重量列为"成本优化"选项。
- **根因**：成本文章天然想问"怎么能更便宜"，而最便宜的答案往往违法。
- **现在拦它**：写手规则（必须同时写出法律要求与处罚暴露）。

### 5. 两个不同端点的差被并列成对比
- **现象**：1.9 是低位端点之差（45.6−39.8），5.8 是高位端点之差（50−48.1），并排写成"每家差多少"。
- **根因**：区间数据的差必须端点对端点，混用会造出一个不存在的量。
- **现在拦它**：审核意见（区间端点必须对齐）。

### 6. 置信度小节与正文互相打脸
- **现象**：一边说"35% 已确认"，一边说"现行税率未知"，正文却当已知用。
- **现在拦它**：审核意见 + `figure trace`。

## 二、重复与唯一性

### 7. 同一事件发了两篇
- **现象**：beef safeguard 两篇，一个 11-01，一个 11-03，标题一模一样。
- **根因**：查重比对"数字 + 主题词干"，不比对标题；而两篇数字几乎一样仍被放过。
- **现在拦它**：发布前 `fitTitle`（标题重复直接拒发）＋ CI `titles and descriptions`（全站标题唯一）。

### 8. 删掉文章后没清入链
- **现象**：删重复页后，两篇旧文的入链变成坏链，CI `internal links` 红。
- **根因**：入链是自动加的，删除时没人回收。
- **现在拦它**：删文章必须同时搜 slug 并清句子（已做过一次，写进流程）。

## 三、顺序错、作用域错（"改了但没生效"的家族）

### 9. 内链修复放在质检之后
- **现象**：连续三天 `L1 internal links` 拒稿，三次修订分数 200→200→200 不动。
- **根因**：修复写进了"发布阶段"，而质检在它之前把草稿放进站点跑闸门。修复永远晚一步。
- **现在拦它**：修复移到写手之后、质检之前。

### 10. 默认值在说谎
- **现象**：`information_gain` 字段为空就填 `primary-source`，而流程指南正文没有任何文件编号 → B 线在最后一步被拒，32 次调用白费。
- **根因**："字段缺失就填一个值"没问过"这个值永远为真吗"。
- **现在拦它**：按正文是否真有文件编号来定，没有就填 `custom-calculation`。

### 11. 变量作用域
- **现象**：`reasons is not defined` —— 文章已 stage，进程崩溃在发布之后。
- **根因**：那个作用域里变量叫 `run.reasons`；`node --check` 查不出这种错。
- **现在拦它**：发布后崩溃会留痕在 `data/qa-loop.jsonl`。

### 12. 语料过滤插到声明之前
- **现象**：`ReferenceError: Cannot access 'corpus' before initialization`，research 每次启动即崩。
- **根因**：`const` 的 TDZ 在运行时才炸，`node --check` 通过。
- **现在拦它**：崩溃不再伪装成 NO-SUBJECT（红卡 `RESEARCH-CRASHED`）。

## 四、闸门与告警本身曾经失真

### 13. 审稿判决"no parseable verdict"整整一个月
- **现象**：日志永远是 `reviewer: no parseable verdict`。
- **根因**：`qaOut` 是 stdout+stderr 拼接，stderr 每次都带一条 UNDICI 警告，`JSON.parse` 必然失败。
- **现在拦它**：先从文本里抽出最外层 `{...}` 再解析。

### 14. 只报数量不报名字
- **现象**：`L1 1 gate failure(s)`，三天查不出是哪道。
- **根因**：正则期待 `[FAIL] xxx`，而闸门表的格式是 `FAIL    0.2s  internal links`。
- **现在拦它**：正则改正则，detail 里写出名字。

### 15. 崩溃被报成"今天没题"
- **现象**：research 崩了，卡片是 🟡 NO-SUBJECT，读起来像"官方今天没发新东西"。
- **现在拦它**：`RESEARCH-CRASHED` → 🔴 红卡。

### 16. 子进程失败只说 "Command failed:"
- **现象**：advisory 层失败，理由只有命令路径。
- **现在拦它**：打印子进程 stderr 尾部。

### 17. 复审日期过期 → CI 红
- **现象**：两篇文章的 `reviewBy` 过期一天，CI 连红两次。
- **根因**：日期维护只挂在 A 线。
- **现在拦它**：三条线跑前都顺延；日期必须不带引号写。

## 五、流程与运维

### 18. 一次改八处，结果无法归因
- **现象**：2026-11-02 到 11-04，A 线改了八处（源数、文章数、语料、去重、种子、审稿降级、合规、轮换），当天仍然失败，判断不了是哪一处。
- **教训**：改一处，跑一次，看证据；否则"修好了"只是感觉。

### 19. 只在云端跑的脚本，没有本地跑过就推
- **现象**：`research.mjs` 两天内被改坏两次，都是云端才发现。
- **现在拦它**：改 research/cloud-* 之前先本地 `node --check` ＋ 用小参数跑一遍。

### 20. PowerShell 重定向写文件
- **现象**：`>` 写出 UTF-16，捕获的 JSON 全坏。
- **现在拦它**：用 Node 里的 `execFileSync` 捕获。

### 21. 多行 splice 破坏文件
- **现象**：`agent-run.mjs` 被一次替换删掉 237 行；`cloud-orchestrator.mjs` 两次被破坏。
- **现在拦它**：单行替换 + `node --check` + 从远端恢复。

### 22. 机器人的提交不触发 CI
- **事实**：用 `GITHUB_TOKEN` 推的提交不触发其他工作流。
- **后果**：每日发布的文章没有 CI 记录，唯一兜底是流程内的"发布后闸门"。

### 23. 改了却没生效（缓存）
- **现象**：删掉的页面线上仍 200，sitemap 已经没有它。
- **结论**：Cloudflare 边缘缓存；下次部署或缓存过期才消失。**sitemap 是最快的真相来源。**

### 24. 手动重跑制造卡片噪声
- **现象**：一天收到 6 张黄卡，其实是一次故障被反复重试。
- **现在拦它**：当日已发布 → `ALREADY PUBLISHED TODAY` → 不发卡。

## 六、审核体系自身的教训

### 25. 审稿人看不到源文档，所以它的否决权必须有限
- **现象**：L5 连续给出 10 条"有引用"的意见，全部指向"需要一份没抓到的文件"，改写无法回应，A 线三天零产出。
- **结论**：L5 的意见改为**记录不拦发布**（2026-11-02）。代价是必须写进 `data/lessons.jsonl` 并在卡片上写明 `PUBLISHED-DEGRADED`。
- **反过来**：正因为它不再拦，才需要 `figure trace` 这样的机械闸门接住"假设基线"。

### 26. 写手规则写进提示词 ≠ 模型会遵守
- **现象**：11-05 加了"不许用未知基线算数"，11-06 又犯一次。
- **结论**：**能被机械检查的，就不要只写在提示词里。** 提示词管风格，闸门管事实。

## 七、给两个 AI 的直达清单

**写手必须自问（每次交稿前）：**
1. 正文里每个金额、每个百分比，来源是 figures 里的哪一条？找不到就别写。
2. 我引用的文件名、条款号、程序名，材料里有没有这个字符串？
3. 我有没有替政策解释动机？
4. 我有没有把违规写成选项？
5. 我的置信度小节和正文说的是同一件事吗？
6. 数字是区间时，两个端点我对齐了吗？

**审核必须优先看：**
1. 有没有在未声明的基线上做算术（最高频、最贵）。
2. 断言与它自己引用的单一来源是否一致。
3. 置信度小节是否诚实。
4. 区间端点的配对是否正确。
5. 有没有把违规写成选项。
