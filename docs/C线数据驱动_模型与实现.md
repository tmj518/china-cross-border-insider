# C 线的数据驱动：模型、实现、以及第一次测量打脸

> 2026-10-26。A 线冻结，B 线不动，只改 C 线。
> 这份文件回答一个问题：**凭什么决定下一篇指南写什么**。

---

## 1. 为什么是 C 线

三条线的分工是「稳中有变」：A 稳、B 变、C 介于两者之间且可测量。

- A 线的产出是「部委今天发了什么」——数字硬，但 90 天 GSC 证明这类题材在英文搜索里几乎没有需求（27 个查询里，只有 5 个是买家意图，各 1 次曝光）。
- B 线 9 次运行 0 次自主完成，成本是 A 的 12 倍，它现在的作用是「每天复制一遍 A」。
- C 线的产出是**程序性指南**——「怎么办 X」。这类内容对零权重的新站有两个好处：长尾、且读者要的是一个步骤而不是一段观点。

所以 C 线是唯一**既有真实需求、又能被数据闭环管理**的一条。

---

## 2. 模型：三个因子相乘，任何一个是零就是零

```
priority = demand × intent × gap
```

| 因子 | 怎么量 | 为什么是乘法 |
|---|---|---|
| **demand** | GSC 90 天里与该主题匹配的曝光，`log(1+imp)`，封顶 5 | 没人搜的题，写得再好也是零 |
| **intent** | 查询里有没有程序性词（how / requirements / documents / permit / account / fee…）→ 1.0，否则 0.6 | 想看故事的人和想办手续的人，要的不是同一篇 |
| **gap** | 没页面 1.0；有页面但 >20 名 0.5；≤10 名 0.1 | 已有的排名是资产，写第二篇会分裂信号 |

**乘法而不是加法**，因为三者是「与」的关系：无人搜索 × 精准意图 = 0；强需求 × 已有第 3 名 = 浪费。

## 3. 先验：数据不够时怎么办

90 天只有 27 个查询，绝大多数候选主题**匹配不到任何查询**。如果严格按 measured demand 算，全是 0，一篇都不写——这正是这套系统反复栽过的坑（规则把系统锁死）。

所以：

```
demand > 0  →  用 measured
demand = 0  →  用 prior（按题类），并在输出里标 basis: "prior"
```

先验表是显式的、写死在代码里的：

| 题类 | 先验 | 理由 |
|---|---|---|
| tax / residence | 3.0 | 每个新到的人都要过 |
| work-visa / employment | 2.8 / 2.6 | 雇主要办、员工要等 |
| social-insurance | 2.5 | 与工资直接挂钩 |
| driving / relocation | 2.2 / 2.0 | 落地后才想 |
| transit | 1.8 | 一次性 |

**关键纪律：先验永远不与实测相加，只做替代。** 一旦有查询匹配上，measured 接管，prior 归零。混着用的先验无法审计。

---

## 4. 反馈：另一半是记分卡

规划只解决「下一篇写什么」，不解决「上十篇有没有用」。同一个工具每次运行都输出：

```
每篇已发布指南：曝光 / 点击 / 排名 / 文章级入链数
```

因为「两周了还是 0 曝光」有两种完全相反的解释：

- **没人搜这个词** → 换题
- **有人搜但这个页面没排名** → 补链、改标题，别换题

不做这个区分，规划器就只是在猜。

---

## 5. 第一次测量：打脸

```
已发布指南   10 篇
有曝光的     0 篇
文章级入链   0 条（10/10 全是 0）
```

**两个零是同一个零。** 一个没有任何页面指向它的页面，爬虫没有理由给它排名——这和「选题对不对」无关。

所以第一次运行就推翻了「继续加题」这个默认动作：**先补链，再加题**。

已做：
- 50 篇博客文章各加一句指向 `/guide/` 索引（49 篇）或具体指南（1 篇）
- 索引现在有 49 条入链（之前只有导航）

还剩：9 篇指南仍然只通过索引可达。下一轮应该由**内容相关性**把它们和具体文章连起来，而不是再写第 11 篇。

## 6. 什么情况下这个模型算错的

写下来是为了以后能拿它打自己：

| 观察 | 说明模型哪里错了 |
|---|---|
| 补链 4 周后，指南仍然 0 曝光 | 不是链接问题，是这些词**根本没人搜**——先验表整体偏高，C 线应该减产 |
| 有了曝光但点击率 < 0.5% | demand 抓对了，**intent 抓错了**：搜的人想要的是另一种东西 |
| 排进前 10 的页面里，gap 判为 1.0 的题目占多数 | gap 的阈值（20 名 / 10 名）设错了 |
| 规划出的前 3 名和实际发布后的表现完全无关 | 先验就是错的，应该退回纯实测，宁可少写 |

## 7. 落地在哪

| 文件 | 作用 |
|---|---|
| `tools/plan-guides.mjs` | 算分、写 `priorityScore` 到题库、输出记分卡、报告「只通过索引可达」的页面 |
| `tools/link-guides.mjs` | 按主题匹配给指南补入链（够得着具体指南就指具体，否则指索引） |
| `tools/link-to-hub.mjs` | 通用版：把任意页当 hub，给全站补链（calculator 用的就是它） |
| `tools/c-line-orchestrator.mjs` | 候选按 `priorityScore` 排序；无分的排最后，所以旧题库行为不变 |
| `.github/workflows/c-line-daily.yml` | 15:20 先跑规划，再写稿；GSC 读不到就退回先验，不阻塞出稿 |
| `data/guide-plan.json` | 每次规划的快照，含每个分数是怎么算出来的 |
