**现象：** 两个会话共用 `C:\Users\tmj19\Desktop\出海官网更新工作流`，同时写 git 工作区。

```
A 会话：改 tools/research.mjs，想 push
→ git pull --rebase 失败：“You have unstaged changes”
→ 因为 B 会话正在跑流水线，工作区里有 10 个脏文件
```

**处置（本次做法，推荐沿用）：**

```
★ 不 stash、不 reset、不 checkout -- .
★ 把自己已提交的改动推到旁支：git push origin HEAD:refs/heads/<分支名>
★ 主线与对方的未提交工作都不动
```

**规矩：**

```
动手前  git status --porcelain
        为空   → 可以写
        不为空 → 只读，不 rebase / 不 stash / 不 push

永禁    git stash、git reset --hard（本轮之前已因此丢过两个文件）
交接    写完就 commit + push，然后一句话通知
```
