# 双会话协作协议（项目管理 ↔ 项目执行）

一个工作区，两个对话框：**项目管理**负责定优先级、验收、拍板；**项目执行**负责改代码、跑流水线、交证据。
两者不互相发消息，**通过这个目录里的文件交接**——用户不需要复制传话。

---

## 1. 文件分工（各写各的，永不并发写同一文件）

| 文件 | 谁写 | 谁读 | 用途 |
|---|---|---|---|
| `docs/collab/看板.md` | **项目管理** | 执行 | 当前目标、优先级、待验收项、已批准/已否决 |
| `docs/collab/收件箱.md` | **项目管理** | 执行 | 一条一段，有序号，只追加不改写 |
| `docs/collab/回报.md` | **项目执行** | 项目管理 | 每轮一条：做了什么、证据、卡点。只追加 |
| `docs/collab/协议.md` | 双方（改动需在收件箱留言） | 双方 | 本文件 |

**规则：**
- 只**追加**，不改别人写过的段落；要修改自己的旧条目，在新条目里写明"更正 #N"。
- 每条必须以 `## [序号] YYYY-MM-DD HH:mm BJ — 谁` 开头。
- 执行每轮**开头读** `看板.md` + `收件箱.md` 未完成的条目；**结尾写** `回报.md` 一条。
- 项目管理每次看进度只读 `回报.md` 末尾三条 + 四层校验输出。

---

## 2. 唯一的"状态真相"是四层校验，不是任何一方的说法

```bash
node tools/verify-four-layers.mjs
```

| 层 | 含义 | 判定 |
|---|---|---|
| 1 | 本地磁盘上的代码 | 与第 2 层逐字节一致 |
| 2 | GitHub main | HEAD 可读 |
| 3 | 最近一次 Actions 运行 | `data/runs/latest.json` 有 verdict |
| 4 | Cloudflare 线上 | 文章 URL 返回 200 且在 sitemap |

**任一层 FAIL = 不接受"已完成"的结论。** 报告时必须贴这个命令的完整输出。

## 3. 项目管理怎么下达任务（收件箱格式）

```md
## [007] 2026-11-11 09:00 BJ — 项目管理
目标：A 线连续 3 天在 07:20 自动产出成本稿
验收：每天 07:20 的 run 日志含 "CLOUD ORCHESTRATOR started: true" 且 verdict PUBLISHED
期限：11-13 07:20
禁止：改闸门判定、加 GitHub cron、动 CF Worker
```

## 4. 执行怎么回报（回报格式）

```md
## [007] 2026-11-11 12:30 BJ — 项目执行
对应：#007
改动：<commit sha> <一句话>
证据：<四层校验输出> + <run id + 关键日志行>
状态：完成 / 部分 / 卡住（卡住必须写"卡在哪一层")
```

---

## 5. 并发与冲突

- 两个会话**同时**写同一文件会互相覆盖。上面的分工就是为了不发生这件事。
- 若必须改同一文件，项目管理先写收件箱，执行改完在回报里登记，PM 再基于回报更新看板。
- 本地工作区没有 git 历史可回滚（推送到 GitHub 是通过 API 做的），**所以任何删除/覆盖前，先 `cp` 一份到 `out/backup-<时间戳>/`**。

---

## 6. 已知边界（不要假装有）

- 两个对话框**不能互相推送消息**：没有这个通道。协作靠"对方下次运行时去读文件"。所以实时对话不行，异步交接可以。
- 项目管理会话第一次启动时，需要用户说一句"按 docs/collab/协议.md 开工"，之后它自己会读看板和回报。
- 这一条要写进 PM 会话的第一条消息里，否则新会话不知道有这个协议。

## 巡检机制（自动唤醒，用户不必传话）

- **项目执行**（本会话）已设：每 30 分钟自动唤醒一次 → 读 `收件箱.md` → 有新条目就执行并写 `回报.md`；没有就跑四层校验写一行。
- **项目管理**（新会话）需要自己设一条，第一句话贴：
  ```
  你是项目管理。按 docs/collab/协议.md 工作。并设一个每 30 分钟的巡检：读回报.md 与看板.md，
  有新增则更新看板并在收件箱.md 追加下一条任务（编号接续）；没有新增则保持沉默。
  ```
- 两条巡检错开半周期（执行 :00/:30，PM :15/:45），交接不会撞车。

## 边界（唯一需要知道的限制）

- 会话只能被"用户消息"或"自己的定时器"唤醒；两个会话之间没有直接消息通道。
- 因此这不是"实时对话"，是"每 15-30 分钟自动交接一次"，中间不需要人。
- GUI 关闭期间定时器不触发；重开后只补最近一次。

## 自动同步：云端 → 本地

```bash
node tools/sync-from-github.mjs          # 镜像 tools/ src/ docs/ data/ .github/ 与配置文件
node tools/sync-from-github.mjs --check  # 只报落后多少，不改任何东西
```

- 状态记在 `.sync-state.json`（记录上次镜像的 commit）。
- 只复制，不删除本地独有文件；被占用而跳过的文件会列出来。
- **项目执行**的 30 分钟巡检第一步就是跑同步，所以本地最多落后 30 分钟。
