# 闸门清单与仓库底线（写作者与审核者都必须知道的标准）

> 这份文件是**唯一事实来源**的文字版。`tools/site-rules.mjs` 里的 `SITE_RULES` 由它派生，写手与审核两边都 import 那一份，不许各写一份。
> 最近一次核对：2026-11-13，对照 `tools/qa-check.mjs`、`tools/gate.mjs`、`tools/cloud-qa.mjs`、`src/content.config.ts`。

## 一、仓库底线：一篇文章要"存在"必须满足什么

| 项 | 要求 | 不满足会怎样 |
|---|---|---|
| 位置 | `src/content/blog/<slug>.md`（流程稿进 `src/content/guide/`） | 构建不收录，页面不存在 |
| 文件名 | 只用小写字母、数字、连字符；就是 URL 的 slug | 上线 404 或与既有 slug 冲突 |
| frontmatter | `title` `description` `publishDate` `category` `audience` `priority` `target_keyword` `search_intent` `information_gain` | `astro build` 直接失败（zod schema） |
| 时间字段 | `publishDate` 是发布日；`reviewBy` 必须**六个月以后** | 被 `reviewBy declared` / 审稿检查拦 |
| figures | 每个数字一条 `- value:` 记录，五段齐全：数值、单位、期间、来源、检索日 | `figure five-part records` 阻断 |
| 内部链接 | 至少 2 条，且**只能指向真实存在的页面**（`draft: true` 也不行） | `internal links` 阻断（2026-11-13 就卡在这） |
| 草稿 | `draft: true` 的稿不入站；也不许被链 | 链接检查判为断链 |

## 二、构建闸门（CI 每次跑 10 道，`node tools/gate.mjs --fresh`）

| # | 闸门 | 级别 | 具体标准 |
|---|---|---|---|
| 1 | structural gates（`qa-check --all`） | **hard** | 见第三节 21 条，任一 BLOCK 即红 |
| 2 | internal links（`link-check`） | **hard** | 断链 0、孤儿 0（无出链的文章 0） |
| 3 | reviewer agent（`reviewer-check`） | soft | 审稿器结构检查 |
| 4 | structured data | soft | 每页 JSON-LD 可解析 |
| 5 | text contrast | soft | 正文与注释文字达 WCAG AA |
| 6 | titles and descriptions | soft | 每页标题唯一、描述在长度区间 |
| 7 | content security policy | soft | CSP 头齐备 |
| 8 | information gain（network） | slow | 与竞品页比对，不得重复既有信息 |
| 9 | mobile layout（browser） | slow | 375px 无横向溢出、无遮挡 |
| 10 | — | — | 10 道里 hard 全过才算出绿 |

## 三、`qa-check` 的 21 条阻断规则（逐条标准）

| # | 规则 | 具体阈值 |
|---|---|---|
| 1 | text encoding | 文件必须是 UTF-8，无乱码 |
| 2 | figure five-part records | 有数字就必须有记录；无数字则必须 `figures: []` 且正文不出现金额/百分比 |
| 3 | information_gain declared | 必须是 `primary` / `cross-source` / `analysis` 之一 |
| 4 | primary-source cited | 正文必须出现可识别文号（如 `2026年第XX号`、`FR 12345`） |
| 5 | target_keyword declared | 必填 |
| 6 | reviewBy declared | 必须存在且 ≥ 发布日 + 6 个月 |
| 7 | calculation shown to reader | 有换算就必须把算式写出来 |
| 8 | AI summary 40-100 words | 摘要 40–100 词 |
| 9 | V6.2 sections | 必须含：What happened / Why now / So what / Use（For you）/ The data point；2026-10-08 起加 **How confident** |
| 10 | How confident section present | 同上 |
| 11 | How confident has all three parts | 三段式：哪些确定 / 哪些不确定 / 读者该怎么用 |
| 12 | FAQ 3-5 questions, 80-150 word answers | 3–5 问，每答 80–150 词 |
| 13 | comparison table present | 至少一张对比表（解读稿可为定性表） |
| 14 | definition block present | 至少一个 `>` 引用块，引用原文定义 |
| 15 | audience segments >= 3 | 三类读者场景 |
| 16 | no URLs in body | 正文不许出现裸链接 |
| 17 | no hedging words | 禁 may/might/could 之类模糊词（允许 "may sign" 这类许可动词） |
| 18 | no evasion offered as a lever | 不许把低报/错分类/拆单写成省钱手段（2026-11-12 新增，阻断） |
| 19 | no motive without a cause | 不许把执法案例写成修订动机；figures 无因果就只能写"同期发生"（2026-11-12 新增，阻断） |
| 20 | no AI cliches | 禁 "in today's fast-paced world" 等套话 |
| 21 | sensitive-term screen | 禁涉政/涉灾/敏感表述 |

## 四、审稿 L5 的 9 项（advisory，只记录不阻断，但进 `data/lessons.jsonl`）

1. 数字没有五段记录，或没有数字却不声明是解读稿
2. 拿基线做算术，而 figures 里没有那个基线（假设的现价/汇率）
3. 编造文号、条款号、流程名
4. 给措施归因动机、历史或"更大布局"
5. 把不合规写成成本杠杆
6. 跨档位端点相减当对比（low − high）
7. 置信段与正文自相矛盾
8. 重复报道已覆盖的事件
9. `reviewBy` 不足六个月

## 五、三条线各自的"发布"定义

| 线 | 触发 | 成功的定义 |
|---|---|---|
| A（成本稿） | 每日 07:20 + 09:20 备份 | `conclusion=success` 且当天有 `publishDate=今天` 的 blog，线上 200、sitemap 收录 |
| B（agent） | 周日/二/四 20:20 | 同上，且 verdict 不得为 REJECTED |
| C（guide） | 每日 15:20 | 同上，guide 目录 |

**时钟在 Cloudflare Worker，不在任何个人电脑上。** 2026-11-12 的 07:20 / 09:20 / 15:20 / 20:20 四个班次都不是人点的。
